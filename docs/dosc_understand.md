# Как устроена документация проекта

Эта памятка объясняет назначение файлов в `docs/`. Паспорта отдельных skills (`docs/spec/skills/`) и архитектурные решения (`docs/adr/`) здесь не перечислены. Для начала работы открой [карту документации](index.md); карты помогают найти правило, а нормативный текст находится в соответствующем разделе спецификации.

## Файлы в `docs/`

| Файл | Для чего используется |
|---|---|
| [index.md](index.md) | Главная точка входа: показывает, какие документы читать для разных задач. |
| [dosc_understand.md](dosc_understand.md) | Кратко объясняет назначение каждого файла документации вне `skills/` и `adr/`. |
| [skills-map.md](skills-map.md) | Показывает зоны ответственности skills и их общие зависимости. |
| [workflow-map.md](workflow-map.md) | Сопоставляет типовые сценарии с последовательностью skills. |
| [retrieval-map.md](retrieval-map.md) | Ведёт к правилам поиска, адресного чтения и RAPTOR-индекса. |
| [data-model-map.md](data-model-map.md) | Ведёт к описаниям сущностей vault и проверкам их структуры. |
| [defaults-map.md](defaults-map.md) | Помогает найти принятые настройки по умолчанию. |
| [algorithms.md](algorithms.md) | Описывает последовательность действий при поиске, записи, индексации и исследовании. |
| [planning.md](planning.md) | Подсказывает, как составить план изменения функциональности и критерии проверки. |
| [verification.md](verification.md) | Перечисляет проверки, которые нужны после изменения поведения. |
| [git-change-record.md](git-change-record.md) | Описывает, как зафиксировать результат работы, проверки и ограничения в Git. |

## Файлы в `docs/spec/`

| Файл | Для чего используется |
|---|---|
| [index.md](spec/index.md) | Главный индекс модульной спецификации и маршрут к её разделам. |
| [foundation.md](spec/foundation.md) | Фиксирует цель системы, границы и общие правила работы с vault. |
| [data-model.md](spec/data-model.md) | Задаёт структуру статей, метаданных, MOC, HUB и индекса. |
| [defaults.md](spec/defaults.md) | Содержит принятые правила и стартовые значения для ранее открытых вопросов. |
| [workflows.md](spec/workflows.md) | Описывает нормативные цепочки ответа, исследования и изменения знаний. |
| [result-formats.md](spec/result-formats.md) | Определяет данные, которыми обмениваются skills и которые возвращают пользователю. |
| [acceptance.md](spec/acceptance.md) | Содержит сценарии для проверки готового поведения. |
| [user-stories.md](spec/user-stories.md) | Объясняет пользовательскую цель функции и связывает её с требованиями. |
| [requirements-registry.md](spec/requirements-registry.md) | Хранит коды новых требований, статусы, связи и критерии приёмки. |
| [structure.md](spec/structure.md) | Задаёт устройство спецификации и правила выдачи кодов требований и историй. |
| [governance.md](spec/governance.md) | Описывает порядок развития требований и сохранения трассировки. |
| [technical-references.md](spec/technical-references.md) | Собирает технические источники и сведения о возможностях Obsidian CLI и плагинов. |
| [history.md](spec/history.md) | Сохраняет прежние предложения и вопросы, чтобы было понятно происхождение решений. |
