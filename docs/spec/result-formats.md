## 5. Общие форматы передачи результатов

Это логические контракты; реализация может использовать Markdown, JSON или комбинацию. Не обязательно создавать отдельный файл для каждого промежуточного результата.

| Объект | Минимальные данные |
|---|---|
| Результат поиска | Запрос, vault, путь, название, вид совпадения, retrieval method, ссылка, ранжирование при доступности |
| RAPTOR match | Путь, heading path, node level/ID, summary, score, диапазон исходного текста, parent/children, estimated read cost |
| ChangeSet после записи | `vault_id`, `change_id`, операции create/modify/delete/rename, old/new path, фактический hash и статус применения |
| Vector payload | `source` filename, `source_path` vault-relative, `vault_id`, node ID/level, heading path, исходный диапазон и content hash |
| IndexSyncResult | `change_id`, обработанные пути, удалённые/записанные узлы, hash, статус `indexed/deleted/not_indexable/index_dirty` и ошибка для повтора |
| Fragment | Путь, heading path, точный диапазон, текст, child depth, content hash, фактически прочитанные токены |
| Evidence item | Вопрос/утверждение, точный fragment, непосредственность подтверждения, confidence, retrieval provenance |
| Элемент контекста | Путь, глубина, маршрут/предшественник, направление и тип связи, выбранные разделы, статус чтения |
| Основание вывода | Утверждение, источник, точное место, фрагмент или парафраз, первичный/вторичный доступ |
| CoverageGap | Тема/вопрос, scope, проверенные пути и headings, ближайшее покрытие, недостающее знание, вид пробела, уверенность и ограничения поиска |
| ExternalSearchQueryPlan | Для каждого пробела приоритет, исследовательский вопрос, готовый запрос, язык/варианты, цель, ожидаемый тип источника, критерий остановки и при наличии автор с адресом его упоминания; статус `planned/searched/verified` |
| Новая статья | Целевой путь, роль, текст, метаданные, основания, запланированные и существующие связи |
| Предложение правки | ID, файл и раздел, старая/новая версия фрагмента, причина, источники, зависимости, версия прочитанного файла |
| Предложение связи | Начальный и целевой пути, тип отношения, обоснование, место вставки, статус |
| MOC | Тема, ракурс, summary, terms, вопрос ракурса, родители, дочерние MOC, статьи и аннотации |
| HUB | Markdown-описание, summary, terms, Canvas, этапы, цели/результаты, карточки файлов, переходы и их типы |
| Итог запуска | Параметры, охват, ограничения, созданные материалы, предложения, ошибки, пропущенные действия и отдельный статус синхронизации индекса при записи |

Допустимые статусы чтения: «найдено», «прочитано частично», «прочитано», «недоступно». Для частичного чтения указывать использованные разделы. Необработанные документы нельзя включать в число изученных.

Для контекста полезны три независимых ограничения: глубина, число уникальных заметок, объём читаемого текста. Например, глубина 2 не гарантирует малый объём, если первая заметка ссылается на большой HUB.
