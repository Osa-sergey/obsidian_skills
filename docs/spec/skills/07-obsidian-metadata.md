## 3.7. `obsidian-metadata` — свойства, теги и классификация

**Кандидат для `description`:**

> Формировать и проверять YAML-метаданные заметок Obsidian по принятой схеме vault. Использовать при создании статей, нормализации тегов, настройке поиска и подготовке данных для Dataview или Bases. Сохранять существующие пользовательские поля, контролировать типы и предотвращать размножение синонимичных тегов.

**Вход:** содержание статьи, существующий frontmatter, словарь тегов, тип заметки и профиль vault.

**Обработка:** выбрать тип и статус; для MOC проверить тему, ракурс и `parent_mocs`, для статей — принадлежность MOC, для HUB — метаданные в сопроводительной Markdown-заметке, если она используется; предложить темы и aliases; переиспользовать существующие теги; проверить типы свойств и корректность YAML. Для полей со списками использовать согласованный формат во всём vault. Вложенные структуры не делать основой пользовательского интерфейса свойств. [S4]

**Выход:** YAML для нового файла или предложение изменения существующего YAML; отдельный список новых тегов и конфликтов схемы. Теги, тип и статус решают разные задачи: нельзя считать, что произвольное поле `status` автоматически превращается в тег.

**Пример запроса:** «Подготовь метаданные для этих статей и проверь, не дублируют ли теги существующие».

**Критерий готовности:** YAML разбирается; обязательные поля заполнены; ссылки и типы валидны; неизвестные поля сохранены; значения позволяют выполнять согласованные запросы.

**Вопросы:**

1. **M1 — критично.** Какие поля уже приняты? Можно ли расширять схему или нужно полностью сохранить текущие имена и типы?
2. **M2.** Какой словарь типов нужен: `concept`, `guide`, `comparison`, `source`, `research`, `moc`, `hub`? Какие статусы отражают ваш процесс?
3. **M3.** Какая система тегов удобнее: свободные, контролируемые, иерархические? На русском, английском или с таблицей соответствий?
4. **M4.** Какие поля обязательны для всех заметок и какие только для источников, исследований или учебных материалов?
5. **M5.** Нужны ли постоянные ID, дата последней проверки содержания, сложность, время чтения, prerequisites и уровень уверенности? Как использовать эти поля при поиске?
6. **M6.** Какие реальные запросы нужно поддержать в Obsidian/Dataview/Bases? Например: «все черновики по RAG», «источники за год», «непроверенные статьи без MOC».
