## 3.19. `obsidian-gap-search` — пробелы в теме и план внешнего поиска

**Назначение:** по названному HUB/MOC, теме или статье выявить недостаточно раскрытые вопросы и сформировать проверяемый список запросов для поиска материалов в интернете. Пользователь может указать подозреваемый пробел либо попросить найти его без подсказки. Skill сам по себе **не** выполняет поиск в интернете, не создаёт заметки и не утверждает, что внешние публикации найдены.

**Вход:** тема или путь к HUB/MOC; необязательная подсказка о пробеле; цель исследования и аудитория; доступный scope vault; глубина анализа и бюджет; предпочтительные языки, типы источников и актуальность.

**Порядок работы:**

1. Разрешить HUB/MOC по точному пути; прочитать его краткое описание, этапы/разделы и curated links. Собрать относящиеся статьи, соседние MOC, источники и упомянутых авторов через `obsidian-retrieve(mode=deep)`; сначала читать `## Суть`, затем адресные разделы исходного Markdown. В Canvas смотреть маршрут только если он нужен для оценки покрытия.
2. С подсказкой проверить её тезис о пробеле: поискать синонимы, английские термины и смежные разделы. Без подсказки сопоставить вопросы/этапы HUB с тем, какие определения, методы, ограничения, операции, оценки и источники действительно представлены. Приоритизировать вопросы, нужные для цели HUB, а не перечислять все темы, которых нет в vault.
3. Для каждого кандидата записать имеющееся покрытие с путём и heading, чего именно не хватает, тип (`missing`, `shallow`, `stale`, `contradictory`, `uncertain`) и уровень уверенности. Отсутствие слова в заголовке или пустая поисковая выдача сами по себе не доказывают отсутствие темы. Если доступ ограничен, индекс грязный или достигнут бюджет, пометить вывод предварительным и дать проверочный внутренний запрос.
4. Разложить выбранный пробел на конкретные исследовательские вопросы: обзор подходов, алгоритм, изменение/удаление данных, согласованность индекса, оценка, ограничения, реализация и новые работы по теме — только применимые аспекты. Из терминов существующих заметок построить русские и английские варианты, синонимы, точные фразы и при необходимости ограничения по типу источника. Запрос по имени автора составлять только для автора, найденного в прочитанном материале, с адресом этого материала; имя не угадывать.
5. Выдать ранжированный план запросов, сгруппированный по исследовательским вопросам. Для каждого запроса указать цель, текст для вставки в поисковик, ожидаемый тип результата и признак, по которому результат подтвердит или закроет пробел. Отметить пересекающиеся запросы; при обнаружении достаточного покрытия в vault сократить внешние запросы или сообщить, что они не нужны.
6. По явной задаче исследования передать выбранные запросы `obsidian-research` для реального внешнего поиска и последующего синтеза. Выводы по найденным публикациям возникают лишь после их открытия и проверки; изменение vault проходит обычный `prepare`/`apply` и завершается `obsidian-index-sync`.

**Выход:** `CoverageGap[]` и `ExternalSearchQueryPlan`: scope и проверенные пути; перечень пробелов с основаниями/ограничениями; приоритетные вопросы; запросы с языком, назначением, ожидаемым типом источника и критерием остановки; известные авторы с provenance; следующий шаг. Статус `planned` отличать от `searched` и `verified`.

**Пример:** для `HUB_RAG.md` подсказка «мало о динамическом обновлении GraphRAG» приводит к проверке разделов об индексации и графе, затем к запросам вроде `incremental GraphRAG graph index update nodes edges deletion`, `dynamic GraphRAG document updates consistency evaluation` и `обновление графа знаний GraphRAG при изменении документов`. Если заметка называет исследователя, добавить запрос `<имя из заметки> GraphRAG incremental update recent papers` с адресом заметки. Без найденного имени персональный запрос не добавлять. Эти строки — примеры **плана**, не найденных публикаций.

**Граница ответственности:** `obsidian-query-builder` создаёт Dataview/Bases views внутри vault; этот skill формирует запросы к внешнему поиску. `obsidian-research` открывает источники и делает выводы; `obsidian-gap-search` оценивает локальное покрытие и планирует поиск.

**Критерий готовности:** подсказка проверена, либо самостоятельно найден существенный пробел; ближайшие материалы указаны адресно; список запросов разнообразен и связан с проверяемыми вопросами; авторы и заявления о покрытии имеют provenance. Проверять по [`REQ-RET-0004–0005`](../requirements-registry.md) и [§7](../acceptance.md).
