## 3.11. `obsidian-query` — структурированный отбор материалов

**Кандидат для `description`:**

> Отбирать статьи и MOC Obsidian по метаданным, тегам, связям и вычисляемым условиям через Bases и API Dataview. Использовать для воспроизводимых тематических подборок, фильтрации по ракурсу, получения дочерних MOC, поиска пробелов в метаданных и построения состава этапов HUB. Возвращать структурированные данные с путями, условиями отбора и происхождением результата.

**Статус:** предложен по результатам проверки Obsidian CLI. Требование исследовать способы отбора получено от пользователя; выбор конкретных адаптеров и правил выполнения ещё не утверждён.

**Вход:** vault, движок (`bases`, `dataview-dql`, `dataview-api`), сохранённая выборка или условия, исходная заметка для контекста, набор выходных полей, лимит.

**Выход:** JSON со строками, однозначными путями, использованными фильтрами, временем выполнения, источником запроса/именем view, контекстом заметки, доступными версиями инструментов и признаками ошибки/усечения. Ссылки нормализовать в пути, даты — в согласованный строковый формат. Пустая выборка и ошибка исполнения — разные состояния.

**Порядок:** проверить доступность CLI/плагина и готовность индекса; выбрать сохранённый view либо получить подготовленный запрос от `obsidian-query-builder`; выполнить в нужном vault и контексте; нормализовать результат; проверить пути; передать кандидатов для чтения и анализа. Условия из пользовательского ввода передавать как данные, не вставлять без экранирования в исполняемый JavaScript или shell.

**Границы:** полнотекстовый/нечёткий поиск остаётся у Omnisearch. Этот скилл отбирает по структурированным данным; содержательные выводы требуют чтения статей. Рекурсивный обход `parent_mocs` реализует алгоритм с посещёнными узлами и пределом глубины, используя выборку как вход. Не объявлять его встроенной рекурсивной функцией Bases или DQL.

**Вопросы:**

1. **Q1.** Какой движок использовать основным: Bases для сохранённых представлений, Dataview для гибких запросов или оба?
2. **Q2 — уточнено.** Для создания запросов и представлений выделен `obsidian-query-builder`; `obsidian-query` отвечает за их выполнение и возврат данных. Правила сохранения определений уточняются в V2.
3. **Q3.** Нужна поддержка уже существующих DataviewJS-блоков? Какие из них только выбирают данные, а какие строят пользовательский интерфейс?
4. **Q4.** Какие выборки нужны первыми: MOC по ракурсу, дочерние MOC, статьи без MOC, материалы для обновления, состав этапа HUB?
5. **Q5.** Динамический результат MOC сохранять как снимок для исследования, оставлять живым или хранить оба варианта с датой?
6. **Q6.** Должен HUB использовать сохранённые выборки для наполнения этапов? Когда пересобирать Canvas и как сохранять ручные карточки?
