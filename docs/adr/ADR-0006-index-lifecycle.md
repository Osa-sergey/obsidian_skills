# ADR-0006 — Полная замена векторов изменённого файла после записи

- Статус: Accepted
- Дата: 2026-09-29
- Связанные требования: [REQ-RET-0001/0002](../spec/requirements-registry.md), [skill §3.18](../spec/skills/18-obsidian-index-sync.md), [workflow](../spec/workflows.md)

## Контекст

Прежнее описание предполагало выборочное обновление leaf nodes по hash. Пользователь определил обязательный завершающий этап любой записи vault: удалить embeddings затронутого файла, заново построить его иерархию RAPTOR и записать новые векторы. Для удаления и переименования нужны явные старые пути, поскольку после операции исходного файла может уже не быть.

## Варианты

1. Обновлять только изменённые узлы — экономит вычисления, но усложняет удаление устаревших узлов при изменении структуры и не соответствует новому требованию.
2. Полностью перестраивать весь vault после каждой записи — просто концептуально, но работа не ограничена изменёнными файлами.
3. Обрабатывать только изменённые файлы, внутри каждого удалять все старые векторы и строить все уровни заново — выбранный вариант.

## Решение и причины

Общий write coordinator передаёт deduplicated change set в `obsidian-index-sync` после применения. Сначала удаляются прежние векторы изменённых/удалённых/переименованных файлов. Для Markdown заново строятся узлы article/section/subsection/chunk; для создаваемых системой Canvas и Bases — соответствующие иерархии маршрута и представлений. В payload `source` хранит filename, `source_path` — канонический vault-relative путь, используемый вместе с vault ID для точной очистки. Это сохраняет требуемый порядок и отделяет соседние legacy-файлы с одинаковым названием.

## Последствия и пересмотр

На большом изменённом файле вычислений больше; зато проще проверять отсутствие stale nodes и повторять операцию. Между удалением и записью поиск может быть неполным: состояние `index_dirty` и fallback к Markdown обязательны, успешный результат не объявляется раньше сверки. Существующий индекс без `source_path` требует одноразовой полной миграции; удаление по одному `source` недопустимо. Будущая оптимизация внутри файла требует отдельного изменения требования и измерения на fixture vault.
