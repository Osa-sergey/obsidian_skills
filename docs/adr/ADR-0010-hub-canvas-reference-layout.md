# ADR-0010 — Раскладка HUB Canvas по эталону: описанные карточки, зоны, подписанные связи

- Статус: Accepted
- Дата: 2026-10-04
- Supersedes: —
- Связанные требования: [§3.9 obsidian-hub](../spec/skills/09-obsidian-hub.md), `REQ-NAV-0001`, `REQ-NAV-0002`, `US-008`; уточняет [ADR-0003](ADR-0003-navigation.md) (пара md+canvas остаётся)

## Контекст

Первая реализация `obsidian-hub` строила по одной группе на этап в один ряд, с файловыми карточками без пояснений, без цветов, с рёбрами «next». Пользователь отверг результат (HUB «Разработка через спецификации»). Ручной эталон в vault, `HUB RAG 2.canvas` (167 карточек), устроен иначе: макро-зоны OFFLINE/ONLINE/СКВОЗНЫЕ ТЕМЫ, группы шириной два столбца карточек, вложенные подгруппы, текстовые карточки `[[ссылка|подпись]]` + курсивное описание, цвет как статус, подписанные рёбра с ветвлениями и петлями, узлы-акторы. Заметка `hub vs MOC` определяет HUB как переработанное знание («как это работает»), а не список материалов.

## Рассмотренные варианты

1. Только подкрутить геометрию (двумерная сетка), оставив файловые карточки — дёшево, но не решает главную претензию: карточка не объясняет, зачем материал на этом шаге.
2. Раскладка и содержание карточек по эталону, входная спецификация расширена (зоны, подгруппы, описания, статусы, рёбра, управляющие узлы), добавлен SVG-preview — выбранный вариант.
3. Рисовать Canvas вручную без навыка — теряет проверки, парность md и повторяемость.

## Решение и причины

Вариант 2. Карточка материала — текстовый узел (а не `file`-узел): только так можно показать описание; встраивание файла остаётся опцией `kind: embed`. Описание — обязательный по смыслу элемент (`REQ-NAV-0001`), его отсутствие даёт предупреждение, а не блокировку, чтобы можно было быстро набросать маршрут. Размеры берутся из эталона (колонка 310, группа 690, отступы 26/18) и оценки высоты по длине текста. Проверки расширены: ссылки внутри текстовых карточек, перекрытия, пересечение границ групп. `preview` строит SVG с той же моделью ширины текста, поскольку Canvas без Obsidian не рендерится. Сохранение ручной раскладки (H9) не менялось: `add-card`/`add-stage` только добавляют.

## Последствия

Старая входная форма (`kind: file`) принимается, но даёт карточки без описаний. Высота карточек оценивается, не измеряется; при другом шрифте текст может обрезаться. Цвета-статусы описаны в легенде HUB, а не в схеме vault. Эталон не менялся и не копировался.

## Условия пересмотра

Если появится способ измерять отрисовку (headless Obsidian) — заменить оценку высоты измерением. Если пользователям понадобятся другие значения цветов — вынести карту статусов в профиль vault.
