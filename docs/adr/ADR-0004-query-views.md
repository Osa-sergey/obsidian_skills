# ADR-0004 — Reusable views и отдельное выполнение запросов

- Статус: Accepted
- Дата: 2026-09-29
- Связанные требования: [query §3.11](../spec/skills/11-obsidian-query.md), [builder §3.12](../spec/skills/12-obsidian-query-builder.md), [модель §4.4](../spec/data-model.md), [CLI §10](../spec/technical-references.md), [дефолты §11](../spec/defaults.md) (Q, V)

## Контекст

Запросы Dataview/Bases нужны как живые представления и фильтры для retrieval. Создание текста запроса, исполнение и визуальный рендер — разные события. DataviewJS способен содержать произвольный JavaScript и побочные эффекты.

## Варианты

1. Генерировать каждый запрос заново и считать preview рендером — приводит к дублированию и ложной проверке.
2. Исполнять любой JS из vault — гибко, но небезопасно и непредсказуемо.
3. Разделить builder/executor, вести каталог и классифицировать JS — выбранный вариант.

## Решение и причины

`obsidian-query-builder` строит и вставляет определения, `obsidian-query` исполняет поддержанный контракт и нормализует результаты. Переиспользуемые определения каталогизируются в `System/Queries/`; вставленные блоки имеют стабильный ID. Отдельные статусы `generated`/`executed`/`rendered` не позволяют выдавать статическую таблицу за живой вид. DataviewJS допускается только после классификации как data-only.

## Последствия и пересмотр

Требуются проверки параметров, scope, идемпотентной вставки и доступности plugin API. Настоящий render подтверждается лишь в Obsidian. Расширять разрешённый JS-контракт после конкретных сценариев и тестов побочных эффектов.
