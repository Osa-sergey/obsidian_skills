# ADR-0009 — Бэкенд семантического поиска: LM Studio (HTTP) + Qdrant local mode

- Статус: Accepted
- Дата: 2026-09-29
- Supersedes: —
- Связанные требования: [основа §2.6–2.7](../spec/foundation.md), [дефолты §11 — RAPTOR/лимиты](../spec/defaults.md), [semantic-search §3.13](../spec/skills/13-obsidian-semantic-search.md), [retrieve §3.14](../spec/skills/14-obsidian-retrieve.md), [index-sync §3.18](../spec/skills/18-obsidian-index-sync.md)

## Контекст

Skills 13/14/18 требуют реального embedding-модели и векторного хранилища — единственная часть проекта, которой ранее не было ни в коде, ни в окружении. Дефолты §11 называют `Qwen3-Embedding-0.6B`, 1024 dimensions, cosine, «Qdrant local mode как заменяемый адаптер» — явно как стартовую точку, не обязательство («заменяемый адаптер», «стартовые значения, которые настраиваются и измеряются»).

Проверены варианты получения embedding в этом окружении:
1. `sentence-transformers` + PyTorch внутри проекта — запущен, реально работает (тест на `all-MiniLM-L6-v2`), но тянет PyTorch (~2 ГБ) как зависимость проекта и гоняет инференс на CPU без аппаратного ускорения на этой машине.
2. Локальный сервер инференса (LM Studio) с MLX-сборкой модели, доступ по HTTP — пользователь уже поднял `qwen3-embedding-0.6b-mlx` в LM Studio на `http://127.0.0.1:1234`, с OpenAI-совместимым `/v1/embeddings`. Использует Apple MLX (ускорение под Apple Silicon), не требует тяжёлых Python-зависимостей в самом проекте — только `urllib`, как и клиент Omnisearch.
3. Внешний API эмбеддингов (платный/облачный) — отклонён: дефолты явно предполагают локальный режим, платный внешний сервис добавляет стоимость и сетевую зависимость без необходимости.

Хранилище — два режима проверены и работают:
1. `qdrant-client` в locally-embedded режиме (`QdrantClient(path=...)`, без отдельного сервера) — создание коллекции, upsert, cosine-поиск, персистентность на диск.
2. `qdrant-client` поверх HTTP против контейнера `qdrant/qdrant` в Docker (`docker run -d --name obsidian-qdrant -p 6333:6333 -p 6334:6334 -v ~/.claude/obsidian/qdrant_storage:/qdrant/storage --restart unless-stopped qdrant/qdrant`) — по прямому указанию пользователя после первоначального решения в пользу local mode. Тот же API (`QdrantClient(host=, port=)` вместо `path=`), тот же тест (создание коллекции, upsert, delete-by-source_path, cosine query) пройден против реального контейнера.

## Решение и причины

- **Embeddings**: HTTP-клиент к локальному OpenAI-совместимому серверу (LM Studio на `http://127.0.0.1:1234`, модель `qwen3-embedding-0.6b-mlx`), а не встроенная в проект ML-библиотека. Причины: (а) прямое попадание в уже названный в дефолтах `Qwen3-Embedding-0.6B` без изменения нормы; (б) не тянет PyTorch/`sentence-transformers` в зависимости `obsidian_research` — проект остаётся тонким HTTP-клиентом поверх внешнего инференса, как уже сделано для Omnisearch; (в) MLX на Apple Silicon быстрее CPU-инференса PyTorch на этой машине. Хост/порт/модель/токен — часть vault profile (`embeddings:`), по аналогии с `omnisearch:`; сервер и модель — внешняя зависимость окружения, не код проекта, обнаруживается и проверяется как Omnisearch (`bin/obsidian-vault doctor`).
- **Хранилище — режим по умолчанию изменён на HTTP-клиент против Docker-контейнера** (было: `QdrantClient(path=...)` embedded). `VaultProfile.vectorstore.mode` — `"http"` (по умолчанию, host/port из профиля, дефолт `127.0.0.1:6333`) или `"local"` (embedded, оставлен как fallback на машине без Docker — путь на диске, дефолт `~/.claude/obsidian/index/<vault_id>`, W5: state вне заметок и вне git-репозитория проекта). Данные контейнера — volume `~/.claude/obsidian/qdrant_storage`, тоже вне vault и вне репозитория. Причина смены: явное указание пользователя после первой версии этого ADR — предпочтён постоянно работающий сервис (переживает падение/перезапуск процесса, который строил индекс; доступен из нескольких процессов/skills одновременно без блокировки на файле) вместо процесса, встраивающего Qdrant в себя.
- **Размерность и модель — не захардкожены**: `embeddings.dimension` читается из первого реального ответа сервера при первом построении индекса и сохраняется в метаданных коллекции; смена модели/размерности не молча ломает старые векторы, а требует явной пересборки (см. «Условия пересмотра»).

## Последствия

- Появляется новая внешняя зависимость окружения: LM Studio должен быть запущен, а нужная модель — загружена и реально обслуживаться HTTP-сервером (см. эксплуатационную находку ниже); а в режиме `mode: http` — ещё и Docker-контейнер `obsidian-qdrant` должен быть поднят (`docker ps`). Оба обнаруживаются как заведомо необязательные компоненты (по аналогии с G4: «отсутствующий компонент обнаружить и обозначить fallback/недоступную функцию»), а не жёсткая зависимость всего набора skills: skills 13/14/18 деградируют в явный `embeddings_unavailable`/`vectorstore_unavailable`, а не роняют весь набор. `bin/obsidian-vault doctor` должен проверять оба.
- Эксплуатационная находка при подключении: `lms load`/`lms ps` показывали модель загруженной, но HTTP-сервер на порту 1234 отвечал `"No models loaded"` — расхождение между состоянием CLI `lms` и процессом, реально слушающим порт. Устойчиво воспроизведено; решилось загрузкой модели через GUI LM Studio (Developer → Server), а не CLI. Клиент embeddings должен явно и рано проверять доступность (`ping`-подобный вызов), а не считать сервер готовым по одному факту, что порт открыт.
- Векторное хранилище — не источник истины (уже зафиксировано в §2.6: «Векторное хранилище не является источником истины»); полная пересборка по файлу уже определена ADR-0006/REQ-RET-0001–0002 и остаётся в силе для новой инфраструктуры.

## Условия пересмотра

Смена модели или размерности эмбеддинга — повод для полной пересборки индекса (не инкрементальной миграции векторов старой размерности); если это станет частой операцией, стоит формализовать отдельной командой в index-sync, а не считать разовым ручным действием. Если LM Studio регулярно теряет синхронизацию между CLI и HTTP-сервером, стоит пересмотреть выбор в пользу варианта 1 (`sentence-transformers` внутри процесса) несмотря на вес зависимости — отдельным ADR.
