# Индекс архитектурных решений

ADR фиксируют **почему** выбран подход; требования и численные дефолты закрепляются в [спецификации](../spec/index.md). При изменении решения создавай новый ADR, укажи `Supersedes: ADR-NNNN`, старый пометь `Superseded by ...`, обнови этот индекс и затронутые документы.

| ID | Решение | Статус | Причина в двух словах |
|---|---|---|---|
| [ADR-0001](ADR-0001-retrieval.md) | Hybrid retrieval + fragment-first evidence | Accepted | Точность адресного чтения и управляемый контекст |
| [ADR-0002](ADR-0002-writes.md) | Proposal-first для авторского текста | Accepted | Сохранить ручные правки и обеспечить повторяемость |
| [ADR-0003](ADR-0003-navigation.md) | MOC tree и пара HUB Markdown/Canvas | Accepted | Простая навигация, визуальный маршрут без копий |
| [ADR-0004](ADR-0004-query-views.md) | Разделение query builder и executor | Accepted | Проверяемые reusable views и безопасное выполнение |
| [ADR-0005](ADR-0005-modular-spec.md) | Модульная спецификация и паспорт каждого skill | Accepted | Адресное чтение при сохранении исходного текста и ID |
| [ADR-0006](ADR-0006-index-lifecycle.md) | Полная замена векторов изменённого файла | Accepted | Структурная целостность индекса и точное удаление по пути |
| [ADR-0007](ADR-0007-gap-search.md) | Отдельный анализ пробелов и план внешнего поиска | Accepted | Проверяемые гипотезы до поиска внешних источников |
| [ADR-0008](ADR-0008-skill-distribution.md) | Skills на уровне пользователя + реестр vault profile | Accepted | Один skill работает из любого проекта; vault подключается файлом-указателем |

[Шаблон нового ADR](template.md). Нумерацию не переиспользовать. Дату и статус сверять с актуальным решением, не с датой реализации.
