# ADR-0008 — Установка skills на уровне пользователя и профиль vault для подключения проектов

- Статус: Accepted
- Дата: 2026-09-29
- Supersedes: —
- Связанные требования: [G1–G2, §2.2 общий профиль vault](../spec/foundation.md), [паспорта 01–03](../spec/skills/index.md)

## Контекст

Дефолт `G1` фиксирует Claude Code локально и «проектные skills в
`.claude/skills/`», то есть по умолчанию skill виден только в одном
проекте. Пользователь явно потребовал другого: «использовать все скиллы в
Claude и подключать их к проектам и vaults» — один и тот же установленный
набор skills должен работать из любого проекта Claude Code, а какой именно
vault (путь, порт Omnisearch, границы scope, лимиты) он затрагивает,
должно определяться подключением, а не копией кода skill. `G3` также
допускает несколько vault через отдельные profile.

Реализованы первые три skill (`obsidian-search`, `obsidian-context`,
`obsidian-research`, US-001–US-003). Все три требуют одних и те же данные
подключения (путь vault, Omnisearch host/port, scope excludes, лимиты
narrow/deep, соглашение имён) и делят существенный объём алгоритмического
кода (парсинг frontmatter/заголовков, разрешение wikilink, обход графа,
классификация MOC/HUB-имени) — дублировать его в 19 будущих skill нецелесообразно.

## Рассмотренные варианты

1. **Строго по `G1`**: копия каждого skill в `.claude/skills/` каждого
   проекта, путь vault захардкожен в каждой копии. Просто, но пользователь
   явно попросил обратное; 19 skills × N проектов = N копий каждого файла
   для синхронной правки; путь к конкретному vault пришлось бы либо
   зашивать в код, либо повторять в каждой копии.
2. **MCP-сервер поверх vault**: обернуть Omnisearch/filesystem-доступ в
   отдельный MCP-сервер с собственной авторизацией/конфигурацией.
   Более «правильная» долгосрочная архитектура, но существенно больше
   работы (сервер, протокол, установка) ради первых трёх skill; ничего в
   зафиксированных требованиях G1–G7 не требует именно MCP.
3. **Skills на уровне пользователя (`~/.claude/skills/`) + отдельный
   реестр vault profile, к которому проект «подключается» файлом-указателем
   — выбранный вариант.**

## Решение и причины

Код skill живёт в этом репозитории (`skills/<name>/`) и физически
устанавливается один раз в `~/.claude/skills/<name>` символической ссылкой
(`bin/obsidian-vault install-skills`) — доступен сразу во всех проектах
Claude Code, редактируется в одном месте.

Общий Python-пакет `lib/obsidian_common/` (не skill сам по себе — не
содержит `SKILL.md`) даёт всем skill одну реализацию профиля, парсинга
Markdown, Omnisearch-клиента и обхода графа; `Path(__file__).resolve()`
корректно разыменовывает symlink обратно в репозиторий, поэтому
относительные импорты между `skills/*/scripts/*.py` и `lib/` работают и
после установки через symlink.

Профиль vault (`foundation.md` §2.2) хранится вне репозитория, в
`~/.claude/obsidian/vaults/<vault_id>.yaml` — путь к vault на конкретной
машине не является ни исходным кодом skill, ни содержимым статей.
`bin/obsidian-vault register` создаёт профиль; `connect` подключает
конкретный проект двухстрочным указателем `.claude/obsidian-vault.yaml`
(`vault: <id>`). Разрешение профиля при запуске любого скрипта:
явный `--profile` → `$OBSIDIAN_VAULT_PROFILE` → подъём от текущей
директории к `.claude/obsidian-vault.yaml` → единственный
зарегистрированный vault как единственно разумный дефолт → явная ошибка со
списком зарегистрированных vault. Ошибка называет команду для исправления,
а не завершает работу молча и не выбирает vault наугад — это то же
требование однозначности выбора, что и в `foundation.md` §2.3 правило 6
для разрешения wikilink.

## Последствия

Положительные: один источник правды для кода 19 skill; путь vault/порт
меняются без правки skill; несколько vault и несколько проектов
сосуществуют без коллизий (`G3`); механизм не требует сети или базы данных.

Ограничения: symlink-установка — решение для одной машины; перенос на
другую машину требует переустановки (`install-skills`) и повторной
регистрации vault, это ожидаемо и не является миграцией данных vault.
`bin/obsidian-vault install-skills --force` перезаписывает существующую
директорию с тем же именем в `~/.claude/skills/`, которая не является
нашим symlink, — команда предупреждает и требует явного флага, но
решение остаётся на пользователе. Данная схема покрывает G1–G3; она не
регламентирует запуск вне Claude Code (Desktop/Cowork/web) — это отдельная
нерешённая часть G1.

## Условия пересмотра

Появление MCP-подключения к Obsidian (Local REST API, S3 у `technical-references.md`)
для skill 4+ (запись в vault) — веский повод пересмотреть, стоит ли
оставлять filesystem-доступ и текущий профиль как есть для чтения, а запись
перевести на MCP; в этом случае создать новый ADR, а не менять этот. Если
skills этого набора когда-либо потребуется распространять на других людей
или машины пакетом (не symlink), пересмотреть механизм установки в пользу
`scripts/package_skill.py` (skill-creator) с полным копированием, включая
`lib/obsidian_common/` внутрь каждого пакета.
