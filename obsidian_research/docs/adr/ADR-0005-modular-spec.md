# ADR-0005 — Один паспорт на skill и модульная спецификация

- Статус: Accepted
- Дата: 2026-09-29
- Связанные требования: [структура спецификации](../spec/structure.md), [реестр](../spec/requirements-registry.md), [US-013](../spec/user-stories.md)

## Контекст

Единый файл v0.7 содержит 17 паспортов и общие правила. Для точечной разработки его приходится просматривать частями; ссылки на §3.N не помогают открыть только один skill. При разделении нужно сохранить старые номера и формулировки, а также не создать несколько нормативных копий правил.

## Варианты

1. Оставить монолит и несколько индексных карт — проще поддерживать один файл, но каждое адресное чтение остаётся тяжёлым.
2. Полностью переписать требования в новые доменные главы — удобнее организовать, но возрастает риск потери условий и старых ссылок.
3. Перенести исходные разделы без смыслового переписывания, выделить 17 файлов skills и единый индекс — выбранный вариант.

## Решение и причины

Нормативный текст распределён по общим файлам и отдельным паспортам `docs/spec/skills/NN-obsidian-*.md`. `docs/spec/index.md` связывает старые номера §1–12 с новыми путями. Каждый паспорт даёт ссылки на смежные skills, дефолты и user stories. Единый файл v0.7 оставлен архивом только для сверки переноса; прежний путь ведёт к индексу. ID `LEG-*`, `REQ-*`, `US-*` не зависят от расположения файла.

## Последствия и пересмотр

Новые изменения требуют обновить нормативный файл, входной индекс и затронутые карты/ADR. Полнота переноса проверена сравнением всех 28 исходных фрагментов и проверкой локальных ссылок. Если объём общего файла снова мешает адресному чтению, разделить его явной миграцией с таблицей соответствий и без перенумерации ID.
