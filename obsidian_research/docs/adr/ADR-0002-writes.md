# ADR-0002 — Proposal-first для существующего текста

- Статус: Accepted
- Дата: 2026-09-29
- Связанные требования: [author §3.4](../spec/skills/04-obsidian-author.md), [revise §3.5](../spec/skills/05-obsidian-revise.md), [workflow §8.1](../spec/workflows.md), [дефолты §11](../spec/defaults.md) (A, U, W)

## Контекст

Заметки содержат авторский prose, YAML и ручные блоки. Автоматическое переписывание может потерять стиль или обновить файл, изменённый человеком после анализа. При этом generated blocks должны обновляться без ручного сравнения целой статьи.

## Варианты

1. Свободная перезапись файла — быстрее, но риск потери ручного содержимого и конфликтов.
2. Только proposals без применения — безопаснее, но не выполняет явно запрошенный `apply`.
3. Разделить `prepare` и `apply`, а generated blocks адресовать стабильными ID — выбранный вариант.

## Решение и причины

Для существующего prose сначала готовится точный patch. Явная команда или режим `apply` разрешает применение после повторного чтения и проверки актуальности; managed blocks можно обновлять адресно по ID. Новые draft-файлы создаются в разрешённых папках. Change ID и manifest делают действие проверяемым и повторяемым.

## Последствия и пересмотр

Потребуются проверка конкурентной правки, idempotency и конфликтный результат вместо silent overwrite. Merge/split/rename/delete остаются отдельными proposals. Пересматривать уровень автономности только после работы на тестовом vault и явного изменения требований.
