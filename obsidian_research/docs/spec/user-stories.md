# User stories и назначение функций

Истории описывают ценность для пользователя тематического Obsidian vault и разработчика набора skills. Они не подтверждают реализацию и не заменяют точные правила в [модульной спецификации](index.md). Коды требований см. в [реестре](requirements-registry.md); префикс `LEG-` ссылается на неизменённые исходные ID.

### Как пользоваться историями

Перед реализацией найди story, выпиши ожидаемый исход и связанные точные требования. Для внутреннего инфраструктурного шага укажи, какую story он поддерживает; не создавай фиктивную роль ради очередного adapter. При изменении пользовательского исхода обнови story и нормативное требование вместе. Статус реализации ведётся в коде/существующем трекере, не в этой таблице.
